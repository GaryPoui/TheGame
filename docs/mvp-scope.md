# Corte MVP autorizado — 2026-10-23

El usuario autorizó continuar hasta un MVP y hostearlo. Sustituye la restricción de fase documental
para este corte, sin ampliar automáticamente a la campaña completa.

Pregunta: ¿se puede comprender y completar la elección/actualización de urnas con feedback justo,
sin que una mala extracción impida avanzar? Verbo: elegir y volver a evaluar después de observar.
Código a conservar: núcleo puro y validado, presentación desacoplada. Arte inicial original de
primitivas, no requiere Blender ni modelos externos. Una sesión para el corte funcional; revisiones
posteriores corrigen defectos antes de publicar. No se afirma diversión validada sin jugadores.

Incluye: menú, contexto narrativo abreviado, sala representativa, Vera, dos urnas, tutorial preparado,
cuatro rondas exactas U1–U4, ayuda acotada, resumen, práctica, guardado recuperable y ajustes.
Acciones equivalentes en HTML y escena. Las mesas de contratos/registros/final sólo se muestran
como contenido futuro, sin fingir una campaña de 30–45 minutos ya terminada.

Mantener si: un jugador nuevo puede identificar objetivo, tomar una decisión, interpretar el cambio
y terminar. Rediseñar si depende de explicación oral o seguir pistas sin entender. Estos criterios
de experiencia requieren prueba humana; QA automatizado cubre funcionalidad, no esa hipótesis.

Aplicación: prototype-fast acota la pregunta; frontend-design y game-ui-ux aplican identidad de
mesa/expediente; cámara estable y reducción de movimiento; save-systems conserva cada commit;
speckit-implement sigue las tareas y checklists documentales, todas aprobadas antes del corte.
